# Phase 0 research memo — acmg-triage

This memo is generated by `research/phase0/render_docs.py` from harness
`results.json` files. Narrative is the template; every quantitative claim is
substituted from those files. Re-run `make research` after changing a harness.

**Safety.** This project is research / decision-support tooling. It is not a
medical device, not a diagnostic, and not clinical advice. Output requires
review by a licensed molecular geneticist. No patient-identifiable data is
committed or processed in Phase 0.

---

## §1 Problem statement

Clinical genetics labs sit on a pile of variants marked "uncertain
significance." Each one still needs a person to walk through a published
checklist of 28 evidence codes and combine them with a rule table. That review
is slow, two labs often disagree, and the reason for the call is usually a
sentence in a spreadsheet rather than a record someone else can audit.

The people who pay for that are patients waiting on a result, labs paying
curator time, and clinicians who inherit a label they cannot re-check. The
obvious fix — "just look it up in ClinVar" — fails when the variant is novel,
when submitters disagree, or when the assertion has no evidence trail.

This repo builds a LangGraph agent that accepts a variant and returns an
ACMG/AMP classification with every evidence code, its strength, its sources,
and an explicit conflict or refusal when the trail does not support a single
tier.

## §2 Prior art

| Tool | What it does | Gap |
| --- | --- | --- |
| [InterVar](https://wintervar.wglab.org/) (Li & Wang 2017) | Automated 2015 criteria from VCF annotations | No gene-specific VCEP overlay; no literature nodes; no auditable per-code object |
| [Franklin / Genoox](https://franklin.genoox.com/) | Commercial ACMG assistant | Closed, not reproducible, not a research artifact |
| [Invitae / Sherlock-style pipelines](https://www.nature.com/articles/gim2017114) | Lab-internal ACMG engines | Not open; reasoning not portable |
| [ClinGen Criteria Specification Registry](https://cspec.genome.network/) | Gene-specific overlays | Specifications, not an engine |
| [AutoACMG](https://github.com/bihealth/auto-acmg) / [CAPICE](https://github.com/molgenis/capice) | Computational criteria or pathogenicity scores | Score ≠ 28-code trail; no conflict object |
| [ClinVar](https://www.ncbi.nlm.nih.gov/clinvar/) | Assertions and expert-panel stars | A label store, not a classifier |
| [gnomAD](https://gnomad.broadinstitute.org/), [dbNSFP](https://www.dbnsfp.org/), [VEP](https://www.ensembl.org/info/docs/tools/vep/index.html) | Frequency, in-silico, consequence | Inputs, not a combining step |

Something already "solves" automated ACMG: InterVar does, at the 2015 default
table. Another engine is still worth building because (1) ClinGen VCEP
overlays now dominate expert-panel calls and InterVar does not apply them as
a first-class, testable table, (2) literature codes are either skipped or
hidden inside a black-box NLP step, and (3) conflict is usually collapsed to
VUS instead of being a typed output. The product of this repo is the evidence
trail, not a new pathogenicity score.

## §4 Technical selection

Each choice below is expensive to reverse. Options, criterion, measurement,
decision.

### 4.1 Literature-node model family

Options: gpt-4o-mini, gpt-4o, claude-haiku-4-5, claude-sonnet-4-5, gemini-2.0-flash.

Criterion: USD per variant for three literature nodes (PS3, BS3, PP4), using
measured input tokens and a committed 400-token structured output assumption.

Measurement: `research/phase0/llm_cost/` (n=12 excerpts, tiktoken
cl100k_base).

| model | mean input tok/prompt | input tok/variant (3 nodes) | USD/variant | USD/10k variants |
| --- | --- | --- | --- | --- |
| gpt-4o-mini | 160.2 | 480.8 | 0.000792 | 7.92 |
| gpt-4o | 160.2 | 480.8 | 0.013202 | 132.02 |
| claude-haiku-4-5 | 160.2 | 480.8 | 0.006481 | 64.81 |
| claude-sonnet-4-5 | 160.2 | 480.8 | 0.019442 | 194.42 |
| gemini-2.0-flash | 160.2 | 480.8 | 0.000528 | 5.28 |

Decision: **Default literature model: gemini-2.0-flash ($0.000528/variant). Escalate to a larger tier only when the small-model cache miss fails structured-output validation.**

API round-trip latency: **unmeasured**. The measurement that would settle it
is a live call of the same 12 prompts to each provider, recording p50/p95
RTT. Local render+tokenize was 9.91 ms total.

### 4.2 Combining table representation

Options: nested ifs; Bayesian points (Tavtigian 2018); declarative 2015 rows.

Criterion: the table must be diffable against Richards 2015 Table 5 in tests.

Measurement: `tests/unit/test_combining.py` asserts BA1 short-circuit, 1 VS +
1 moderate = Likely pathogenic, 1 VS + 1 supporting = Uncertain significance,
and PM2+BP4 = Conflicting. That last row is a project rule, not a 2015 row:
2015 collapses conflict to VUS. The spec forbids silent collapse.

Decision: **declarative rows in `src/acmg_triage/combining.py`**. Bayesian
points are `# TODO(v2):` (see ROADMAP in Phase 2).

### 4.3 Default vs gene-specific frequency rules

Options: ship Richards 2015 thresholds only; require a VCEP overlay for
BA1/BS1/PM2; hybrid.

Criterion: per-code F1 of default rules against VCEP-style gold. Ship
default-only if F1 ≥ 0.90 and there are zero strength mismatches.

Measurement: `research/phase0/criterion_agreement/` on 100 variants.

| code | gold+ | TP | FP | FN | precision | recall | F1 | strength mismatches | decision |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| PVS1 | 18 | 18 | 0 | 0 | 1.000 | 1.000 | 1.000 | 8 | needs VCEP overlay |
| PM2 | 60 | 60 | 10 | 0 | 0.857 | 1.000 | 0.923 | 60 | needs VCEP overlay |
| PM4 | 0 | 0 | 0 | 0 | 0.000 | 0.000 | 0.000 | 0 | unmeasured (no gold positives) |
| PP3 | 14 | 8 | 0 | 6 | 1.000 | 0.571 | 0.727 | 0 | needs VCEP overlay |
| BA1 | 20 | 8 | 0 | 12 | 1.000 | 0.400 | 0.571 | 0 | needs VCEP overlay |
| BS1 | 10 | 0 | 7 | 10 | 0.000 | 0.000 | 0.000 | 0 | needs VCEP overlay |
| BP4 | 28 | 28 | 0 | 0 | 1.000 | 1.000 | 1.000 | 0 | default-only |
| BP7 | 0 | 0 | 0 | 0 | 0.000 | 0.000 | 0.000 | 0 | unmeasured (no gold positives) |

Decision: **Ship default-only for BP4. Require a VCEP overlay before shipping PVS1, PM2, PP3, BA1, BS1.**

### 4.4 Orchestration and storage

Options for orchestration: a Python function chain; LangGraph with one node
per code; an ad-hoc agent.

Criterion: every node independently unit-testable with a mocked LLM; typed
state; no hidden globals. Not measured at runtime in Phase 0 — this is a
testability constraint, not a latency measurement. Latency of LangGraph vs a
function chain is **unmeasured**.

Decision: **LangGraph, one node per code, in Phase 2.** Phase 0 implements
only the deterministic rule + combining core those nodes will call.

Options for storage: JSONL of evidence trails; DuckDB; Parquet.

Criterion: local, queryable, no service. DuckDB is the repo convention.

Decision: **DuckDB for batch eval in Phase 3.** Phase 0 writes JSON + Markdown
results. DuckDB vs Parquet scan time on a ClinVar-sized table is
**unmeasured**.

## §5 Evaluation design

Hold-out (Phase 3, not run here): ClinVar variants with expert-panel
(3-star) review status.

Metrics, declared before any model is built:

- Concordance with expert panel, overall and per ACMG tier
- Confusion matrix across the five published tiers plus Conflicting
- Per-criterion precision/recall vs ClinGen published assignments
- Baseline: frequency-threshold-only classifier (BA1/BS1/PM2 only)
- Second baseline: this Phase 0 rules-only system
- Separate score with literature nodes disabled (must equal the rules-only number)

Split: pinned, committed split manifest. Seed 0. No random reshuffle in CI.

**Failure condition (written before the answer):** the project fails if, on
the expert-panel hold-out, the full system does not beat the rules-only
concordance measured here (0.670) by at least 5 absolute
percentage points, **or** if the literature-disabled run disagrees with the
rules-only run, **or** if any Conflicting gold record is emitted as a single
tier.

Phase 0 rules-only concordance against the VCEP-style probe set:

Rules-only concordance = 67/100 = 0.670. Zero-LLM code fraction = 0.607 (8+9/28).

## §6 Cost and scale model

Literature-node cost is measured in `llm_cost`. Compute for the rules path
is local CPU: applying eight if-statements to 100 variants is not a cost
center. Numbers:

- Mean input tokens / literature prompt: 160.2
- Input tokens / variant (3 nodes): 480.8
- Cheapest / variant: Default literature model: gemini-2.0-flash ($0.000528/variant). Escalate to a larger tier only when the small-model cache miss fails structured-output validation.
- Local tokenize time: 9.91 ms (0.83 ms/excerpt)
- API RTT: unmeasured
- Rules-path CPU on 100 variants: unmeasured as a separate timer (runs inside criterion_agreement; wall time is dominated by process startup)

Unmeasured: VEP-cache disk, gnomAD Hail query cost, ClinVar weekly ingest
wall-clock, human curator time saved. The measurement that would settle
ingest cost is a timed download+parse of `variant_summary.txt` on a 4-core
machine, recorded as seconds and peak RSS.

## §7 Risks

| Risk | Type | Mitigation or acceptance |
| --- | --- | --- |
| Probe-set gold is VCEP-rule-derived, not erepo-exported | Data | Accepted for Phase 0. Memo and harness READMEs say so. Phase 3 replaces the 100 with exported expert-panel records. |
| Default 2015 PM2 strength is moderate; ClinGen SVI is supporting | Technical | Measured. Combining must store strength as a field. S1 is the teaching case. |
| Literature nodes hallucinate a functional-study claim | Technical | Span-level citation + structured output. Uncited `applied=true` is a failed unit test in Phase 2. |
| Output read as a clinical report | Legal | Disclaimer on CLI, API, and README. Not a device. |
| Gene without a VCEP still gets a confident tier | Scope | S5: refuse when the catalog snapshot has no coverage. |
| dbNSFP / gnomAD license drift | Legal | Do not redistribute full databases. Commit ≤5 MB designed samples. |
| InterVar already exists | Scope | Accepted. The gap is VCEP overlays, literature audit, and conflict as a type. |
